# Becoming 長期開發路線圖

狀態：方向紀錄與未來評估，非實作排程。盤點日期：2026-10-15；基準 main：`f46468dd81cd7d37fef722db113e54fdd68a6be1`（PR #18）。

## 現階段：Chapter 1 — 初始之地

Becoming 目前的核心是醫師一階國考學習工具。至 2027/01/16 國考前，優先維持穩定、資料安全及日常讀書效率；採維護模式，先處理實際影響使用的 Bug，不主動新增王國功能或進行高風險重構。

保留現有課程與學習紀錄、今日任務、讀書計畫、首次完成日期、冒險編年史、Lite SVG 王國、三棟建築及領主成長。沿用已驗收的 Design A：課程型任務由課程完成紀錄衍生，一般任務保留獨立狀態。領主 Lv.1–20 由王國進度推導，權重為學院 40%、兵營 40%、要塞 20%；歷史 XP 保存，新版任務不新增 XP。這些是目前基準，本文件不更改公式、I–V 門檻或資料。

穩定維護應保護 Firebase 權限、UID／工作階段隔離、首次 loading／ready／error／signedOut 狀態、離線 pending、衝突提示、課程日期及歷史獎勵。不把未載入視為零進度，不自動清空或重播待核對資料。

## 未來：Chapter 2 與後續章節

第一章完成後，希望延續相同的王國與領主旅程，而非預設清空或重置。未來章節可支援不同人生階段、學習目標或其他長期目標；任何跨章資料延續規格仍須另外設計與驗證。

探索方向包括新領地、建築、奇幻魔法、怪物及更完整的 RPG 系統。這些是保留的創作可能性，**不是已承諾的功能清單**。第二章的具體內容、解鎖方式、世界觀、開發時間，以及如何銜接目前成長，均未定案；不預設國考日期會自動解鎖第二章。

未來若啟動章節規劃，先釐清使用者的新目標，再評估最小功能、資料相容性與維護成本，另行授權。Chapter 2 不直接等於產品 v2.0.0。

## Web-first、App-ready

延續 Web-first、App-ready：維持 Web 為主要可用版本，近期方向是評估未來跨平台安裝，現在不立即移植，也不改用遊戲引擎。

| 評估選項 | 可能用途 | 先確認的事項 |
| --- | --- | --- |
| PWA | 以現有 Web 提供安裝入口 | 平台差異、更新／Service Worker 快取、離線狀態與 pending 安全；不得讓舊版永久滯留 |
| Capacitor | 保留 Web UI，視需要使用原生裝置能力 | Google／Firebase 登入流程、儲存隔離、生命週期、商店發行與維護成本 |
| 必要行動整合 | 回應經驗證的裝置需求 | 僅在有具體需求時選擇能力、權限與替代方案；不預設加入通知等新功能 |

長期保留更完整遊戲體驗的可能性；工具選型、平台、預算與時程尚未確定。App 化不是 v1.0.0 的前置條件。

## 延後的 C 方案與剩餘分類

B 方案已完成純計算、UI／地圖模組及 CSS 分類。根目錄尚有 19 個 JS，原因見 [目前目錄與保留理由](REPOSITORY_LAYOUT_FINAL.md)；JSON、主機入口與初始化契約不因目錄整齊而搬移。

C 方案留待實際需要：逐步拆分大型程式、改善模組依賴、整理初始化及資料流。候選範圍包括 `index.html` 的內嵌學習程式、`workspace.js`、登入入口、規劃／生活 Store，以及同步相關模組；此處未決定拆分介面或新架構。剩餘 JS 可再評估 `src/auth/`、`src/sync/`、`src/workspace/` 等分類，但不是立即搬移指令。

未來最小安全順序：

1. 確認可重現的維護問題與範圍，畫出 Classic Script 順序、全域初始化及 Store／Firebase 生命週期。
2. 建立舊行為測試契約，使用 Fixtures／Mock；保留 UID 切換、延遲回呼、重連、pending 與日期衝突測試。
3. 每次只抽取一個邊界，不改資料路徑、Schema、成長規則或歷史 XP；不得為整齊而移除同步防護。
4. 保留現有 32 個舊資源 URL 與相容模組契約；若未來要退場，另訂舊分頁／快取相容與回退方案。
5. 逐步審查、驗收及另行授權發布；無法安全控制時縮小範圍。

不把既已淘汰的 I3.2 Admin SDK、可信完成 API、操作收據或根節點交易架構重新帶入。
