# A2 工作範圍摘要（未授權／未實作）

名稱：美術技術校準與分層可行性試作。輸入以核准A1.1共同場景為主；不得再擴增裝飾複雜度或調低第五階段。只選奧術學院一棟做可行性試作，不開始全部五階段、不開始升級動畫或真實學習觸發。

## 預期工作與驗收證據

1. 統一正交等角投影及世界尺度：提供投影樣板、軸線、量測方法，核對門窗／樓層及三棟相對尺寸；無法只憑視覺宣稱精準投影。
2. 建立畫布與地面錨點：定義座標單位、原點、錨點、占地範圍、可見邊界與各層offset。輸出可檢查的manifest草案與疊合圖。
3. 透明背景與遮擋補繪：以明暗底測邊緣、半透明效果與陰影，補繪被遮擋屋牆，不用去背單圖假裝完整分層。
4. Academy一棟分層試作：地面／基座、主體、屋頂／塔樓、庭院、獨立星象儀與水晶、旗幟／效果／前景遮擋等按實際需求拆分；相同畫布和錨點，能獨立顯示與還原原概念。圖層切分須以可靠結構為依據。
5. 評估SVG地圖＋高品質2D素材：檢查image節點、投影、命中區、疊放與縮放；若需要程式驗證，先取得明確的獨立零寫入原型修改授權，不直接改正式Dashboard。
6. 載入及記憶體：量測檔案大小、解碼耗時、首屏、記憶體與高DPR成本。桌機和手機實機分別驗證，FPS是待測目標。不得以本輪靜態概念圖的尺寸模擬作效能結論。

## 不能動的內容

Firebase schema/rules、正式資料與同步、登入、XP、課程與首次完成日期、Planner、五階段成長規則、main/staging與正式部署。試作不得讀取會啟動業務寫入的初始化模組。是否建立分支、PR、Preview、部署或Merge，需明確授權，不能由概念驗收推定。

## 尚待A2授權時確認

具體檔案與獨立試作入口、素材處理方式、投影與尺度校準方法、透明層格式及命名、效能裝置矩陣、Git與部署範圍。這是交接摘要，不是已批准的工作清單，也沒有開始任何試作。
