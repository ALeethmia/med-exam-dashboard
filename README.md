# Becoming — Chronicles of Becoming

Your life. Your story. Your world. 每一步成長，都是人生的新篇章。

Becoming 是現實生活目標管理平台；第一章「學者的試煉」以醫師第一階段國考為現實目標，奇幻世界 Aetheria（艾瑟利亞）提供唯讀的成長回饋。沿用 HTML / JavaScript / Express 學習工作台與原有課程、生活、同步功能；考試日期讀取現有 Adaptive Study Planner 設定，預設為 2027 年 1 月 16 日。


`PORT` 預設為 3000。localhost / 127.0.0.1 自動使用本機模式，**不初始化正式 Firebase**。在其他測試主機使用 `?mode=local` 也會啟用本機模式。學習紀錄保存於瀏覽器 localStorage；介面會顯示本機模式。

## 功能

- Becoming 共用版型：總覽、科目、週計畫、行事曆、成長統計及我的王國六個主要導覽。作息、運動與專注計時收在行事曆次導覽。
- 首頁以等寬雙欄呈現今日任務與四科進度，另提供本週進度及近期日程摘要；手機版改為單欄。
- 淺色、深色、跟隨系統模式；選擇保存於 `med_exam_theme`。
- 每日學習規劃器以 Asia/Taipei 日期管理自主安排的任務：跨科選擇章節／課程、自由任務、選填預計分鐘、編輯、完成／取消、上下排序、延後、複製與刪除復原。空白日期不會自動加入預設任務；日期選擇與歷史列表可查看過去或未來安排。
- 每個新任務首次完成獲得 20 XP；改名、排序、延後、取消／重新勾選或刪除／復原均沿用相同 ID，不能再次領取。舊 XP、等級計算及冪等邏輯保持背景相容；介面不再展示獨立角色等級。王國的「我的編年史」保留成就、歷史 XP 與舊時間目標紀錄；本週首次完成數在統計頁顯示，週一重新計算。
- 初次啟用不回填歷史 XP；既有完成紀錄不會被清除或重置。
- 三個基本成就：首次任務、單日三個任務、累積十個任務。無大型 RPG 系統。

已完成共用 Design Tokens、App Layout、首頁及四科清單整理。四科共用課本／課程目錄與章節內容雙欄，首次開啟依教材順序呈現第一章；手機使用章節選單。生理依 FC 照片目錄排列七章、39 節，頁碼與原始 ID 保持一致。讀書週次篩選獨立收合；科目頁只顯示課程、頁碼／時長、完成勾選與進度，不顯示複習建議、重點或筆記。科目頁只管理課程完成進度；今日任務另行記錄，勾選任務不會完成課程。任務的「課程」按鈕會清除科目搜尋／週次篩選、切換章節並定位原始課程。章節選擇保存在 `med_exam_subject_selection_v1`，不寫入 Firebase。

月曆與重要日程在桌面左右並排、窄螢幕上下排列，月曆維持緊湊尺寸並支援鍵盤開啟行程；作息表保留原時段、以簡短課表呈現。統計的 75% 線只代表進度參考，不代表國考及格機率。週計畫當週預設展開、其餘週收合，保留所有原內容、勾選及進度算法；可從任一週開啟課程選擇器，仍須使用者選擇並確認才建立每日任務。原整週勾選仍會依既有算法顯示 100%，介面標明其來源，不與每日任務綁定。既有導覽排序設定保留於 localStorage，六項固定主導覽不再使用拖曳排序。

## Google 登入與私人同步

正式網站必須先完成 Google 登入，且 UID 符合 `owner-config.js` 的 `OWNER_UID`，才會建立 Realtime Database 連線、載入學習介面及重送待同步紀錄。未授權帳號會登出並顯示拒絕訊息；允許的 UID 未設定時，所有帳號均無法開啟學習介面或啟動同步，不會自動將首次登入者指定為擁有者。本機及 `?mode=local` 仍完全隔離正式資料庫。登出會斷開資料庫並重新載入登入畫面，不清除 localStorage 或既有紀錄。

Firebase Console 需啟用 Authentication → Google，並在授權網域加入正式網站網域；若測試 Vercel Preview 登入，該預覽網域也須加入。尚未有 Firebase 使用者時，可先在已授權的預覽網域以本人 Google 帳號登入；`OWNER_UID` 留空時，登入畫面只顯示該次登入的 UID，隨即登出，不啟動學習介面或資料庫。將本人 UID 填入 `owner-config.js` 並使用相同 UID 設定 Database Rules 後，再部署正式站。已授權登入後，側欄「帳號與同步」可查看與複製 Firebase UID。登入不會自動變更 Security Rules：目前到期的規則仍須由專案擁有者更新。

單人使用且不變更原有資料路徑時，可將 Realtime Database 根層存取限定為本人 UID（將下列佔位文字換成網站顯示的 UID，檢查既有子路徑是否還有其他授權規則）：

```json
{
  "rules": {
    ".read": "auth != null && auth.uid === 'YOUR_FIREBASE_UID'",
    ".write": "auth != null && auth.uid === 'YOUR_FIREBASE_UID'"
  }
}
```

此規則由使用者在 Firebase Console 審查並發布，本專案不會部署規則或操作正式資料庫測試。這是單人存取限制，沒有新增多人帳號隔離或資料驗證模型。原公開 Web 設定移至 `firebase-config.js`，API 金鑰第 9 個字元依擁有者核對結果修正為大寫，其餘設定未變；它不是服務帳戶私鑰，也不取代 Security Rules。真實 Google 登入仍須在已授權的部署網域上驗證。

網站端 UID 檢查只限制正常介面流程，不能取代 Database Rules，也不能阻止其他人完成 Google 身分驗證或出現在 Authentication 使用者清單。資料庫必須獨立限制同一個擁有者 UID。`?mode=local` 保留無雲端連線的本機預覽能力。

## 每日任務資料與衝突處理

- 新資料路徑：`gamification/v3/planner/tasks/{taskId}`。每個任務保存 `title`、`date`、`minutes`（選填）、`links`（只含原始課程 path／ID）、`complete`、`deleted`、`order`、`createdAt`、`_versions`（各欄位操作 ID）、`award`（首次完成的 20 XP 與獲獎日期）。不搬移原課程或任何舊遊戲化資料。
- 本機鍵：`med_exam_daily_planner_v3`，包含 tasks 與 pending；本機模式使用獨立 `med_exam_daily_planner_v3_local`，避免預覽任務混入正式佇列。舊 localStorage 鍵與資料維持原樣。
- 每次同步只 transaction 一個 task ID，並只套用修改欄位，保留其他欄位及其他裝置新增的任務。首次 XP 與任務狀態在同一個 transaction 提交；跨裝置只共用一筆 award。刪除使用 tombstone 並永久保留 award，重試不增加 XP。
- 不同欄位合併；同一欄位若相較編輯時的版本已改變，且內容不同，停止該任務同步，保留本機意圖與雲端內容。首頁會顯示兩者，使用者選擇「保留本機修改」或「採用雲端修改」後再同步。沒有依裝置時鐘直接覆蓋資料。
- 失敗的意圖持久保存；登入後連線恢復、online 事件與「重試同步」會重送，處理舊回覆時只清除對應版本的意圖。Firebase 權限拒絕若取消了讀取監聽，修改 Rules 後需重新整理以重新訂閱。
- 延後移動同一 ID；「複製至今天」建立另一個未完成的學習活動，不複製原 award。XP 是自我回報的鼓勵值，不驗證實際投入時間或知識熟練度。
- 最近課程、未完成課程與週計畫只是篩選入口，不自動選取或加入任務。課程清單由既有 `window.studyData` 建立薄型呈現介面，沒有另一份課程資料。

你已發布的根層 `.read`／`.write` 限定擁有者 UID 時，授權會涵蓋新的 v3 子路徑，預期不需增加 Rules。未在 Console 發布任何規則；若實際另有 `.validate` 或其他設定，需在預覽部署由擁有者確認。前端 UID 檢查仍不能取代 Rules。

所有自動化新任務測試使用隔離的本機或 Firebase 替身，驗證兩裝置欄位合併、同欄位衝突、離線重送、XP 去重、刪除保留獎勵、傳送途中再編輯及操作介面。真實新任務 OAuth／跨裝置／網路斷線測試留待已授權的預覽網域由擁有者驗證，沒有使用正式資料庫做測試。

## Quest OS Phase 1：生活目標與體能重建

本次以 main `a70f7ce` 為基準增量開發，沒有改動 Google 登入、OWNER_UID、Firebase 設定、課程 ID、Planner v3 或 XP 規則。沒有資源經濟、城堡、軍隊或額外 RPG 頁面。

### 使用方式

- 首頁「今日目標」讀書摘要直接統計 **今天（Asia/Taipei）** 的 Planner v3 任務，即使規劃器正在查看其他日期，摘要仍顯示今天。時間目標可選填，任務與課程完成分開記錄。
- 「安排休閒」可設定名稱、選填分鐘及完成狀態，清空名稱可取消安排。休閒不發 XP，也不因延長時間發放任何獎勵。
- 行事曆 → 運動計畫 → 訓練設定，可將開始訓練、階段、模式及每週七天安排加入草稿，按「儲存設定」後一起生效。關閉或 Escape 取消不寫入本機或 Firebase。點選日期看完整菜單，逐項勾選後按「完成今日訓練」；動作勾選本身還不代表整體訓練已完成。
- 「修改日期／類型」設定單日覆寫；移到別日會保留原日已開始或已完成的紀錄，只有今天／未來且完全未開始、沒有任何動作紀錄的草稿才移走；過去日期與既有開始／結果紀錄留在原日期。目標日期已有紀錄時須明確確認，原菜單與結果保存於 revisions，可展開查看。已開始或有動作紀錄的日期不會被後續階段切換自動修改；今天及未來的空白安排則跟隨目前階段。日期欄位與週安排可查看歷史及未來日期。
- 八週是四階段、每階段建議兩週的參考架構，**不依日期自動升階，也不限制手動升降階**。可直接選擇階段 1–4、回到階段 1、取消未儲存的變更，或暫停；階段選擇與週設定一起儲存，已有訓練紀錄與歷史日期保留原菜單與結果。暫停會保留既有菜單與紀錄，不能完成新訓練。階段 1 使用坐姿起步；階段 2 起，一般模式依目前動作條件選擇支撐站姿或同類坐姿替代，低強度模式提供減量坐姿或休息。
- 初期坐姿菜單為踝關節活動 10 下、膝伸直每側 8 下、肩胛後收 8 下、手肘彎曲 10 下，均一組。新菜單 3 的步行建議範圍依階段為 5–10／10–15／15–20／20–30 分鐘，可分段，個別日期目標可調整並保留；替代訓練使用一組減量坐姿動作（5／每側 4／4／5 下）。不強制跑步、跳躍、HIIT 或閉眼平衡。
- 「症狀休息」、恢復日、未安排均不列為運動未達標，不扣 XP，不需要補做。既有習慣統計的運動分母排除這些狀態，舊的連續自律數字收起；學習完成率與 XP 算法不變。持續晃動或重心不穩時應先暫停步行並接受醫療評估。

### 規則與限制

每日總時間預算 T 包含固定課及自主讀書。固定課與已知行程按區間聯集扣除，剩餘時間再保留緩衝。例如 360 分鐘、固定課 240 分鐘、20% 緩衝 → 自主時間預算 96 分鐘。休息日、沒有自主時間的日期不安排新任務；固定課仍保留。

先保留固定、已完成、鎖定任務，依核心→一般→彈性、原日期、ID 排序；分散模式選目前未完成任務數最少的可用日期，同數時較早日期優先。任務數用於分散日期，不代表不同課程難度或工時相等。每日任務數上限 `dailyTaskLimit` 選填，預設 null（不限）；舊設定自動採用不限，不改原任務。明確起訖時段檢查衝突及已知時段預算，單元估時不阻擋改期。

`minutes` 不再必填。既有自訂分鐘原樣保留，僅顯示參考；沒有估時也可指定單日、分散或待安排。沒有明確時段的內容標示時間需求未知，不視為零工作量，不保證容量足夠或考前完成。預覽可調整各任務日期，休息日、上限、時段衝突和考前範圍仍會檢查；取消不寫任何資料。確定後只提交日期及 planning。

各科完成／剩餘單元沿用既有科目狀態；本週和近 14 天以目前仍完成的課程／任務之首次完成 award.day 計數，不用安排日期冒充完成日期。舊課程無日期者不納入近期統計並提示。兩種完成紀錄獨立，不換算成工時，不預測完成日，沒有新增完成資料或獎勵。

### 同步與失敗恢復

普通任務操作保留既有欄位版本同步。確認多任務重排後，Planner 把整批寫入可恢復的本機佇列；等待既有單項修改同步完成，再讀最新設定／行事曆，以 Planner tasks 父節點的一筆 transaction 比對所有任務與占用快照後提交日期及 planning。任何任務新增、完成、鎖定或其他實質變動會使整批停止，不部分改期；award 不被重新發放。已提交 token 支援重載後的冪等確認。

離線時顯示「本機已套用、整批待同步」，不宣稱雲端成功。停止時保留預覽與最新雲端紀錄，使用「撤回並重新預覽」；不提供強制覆蓋已完成內容。該批任務待同步時暫時禁止完成／編輯，介面會說明；普通任務仍沿用原離線操作。尚未提交的等待排程可撤回；已開始 transaction 必須等待結果。容量設定有獨立的版本衝突比較與本機／雲端選擇。

任務批次本身具原子性；設定與行事曆在其他節點，沒有跨所有節點的原子鎖。提交前／重連先重新讀取約束，實際 transaction 也比對目前觀察到的約束；若之後設定或行程再修改，畫面會重算負載，需重新確認容量與時段，不會自動搬走固定課。這項限制也適用於手動改固定時段。

life.recordedHabits() 是新增的只讀 getter，列出現有 life store 的 saved.days（沿用 habits 即時監聽與本機 pending 覆蓋），以及已存在 med_exam_habits_YYYY-MM-DD 的舊打卡。沒有額外雲端查詢、寫入、Schema 或同步演算法變更。正常 complete、低強度 alternative 每日期最多計一次；沒有新 exercise 紀錄時才接受明確 daily-sport=true。新版待完成／症狀休息優先，不能被舊 true 覆蓋；archives/revisions 不額外加次數。未來、無效日期不計，課表不產生歷史。若舊快速勾選保留了休息／未安排類型但狀態為完成，資料矛盾時保守不計，介面另列矛盾筆數；原勾選不改。

有效活動日為上述訓練日期與 leisure.status=complete（或沒有新版紀錄時 daily-game=true）的日期聯集，同日兩類只算一天。沒有連續登入、活動時長或每日全類別完成要求。可只靠課程進度升至最高要塞階段；正常休息本身不扣分，修正已完成證據則按目前資料更新。

**歷史限制**：只計已載入的雲端／本機日期紀錄（可能包含待同步修改），不是完整一生的訓練總數。未載入、被刪除或缺日期的歷史無法重建，故兵營在收合的計算說明中標示歷史可能不完整。日期生活紀事只是 habits 所屬日期，資料沒有實際完成時刻。課程事件只接受有效原課程 ID 的新 courseFirstCompletion 日期（自動或手動記錄）；不使用舊 XP 的首次獎勵日期。缺日期的目前完成課程標「日期未記錄」，取消勾選後仍可呈現既有首次日期，但不增加目前單元數。移除日期不回退 XP。

territoryMilestoneSnapshot 只說明「目前達標」，日期為 null；沒有永久升級或歷史解鎖時間證據，不能用首次日期反推出過去階段。realmActivitySnapshot 以原始課程／日期事件 ID 去重，同來源快照重播不增加項目。卡片使用三層資訊：主畫面顯示名稱、目前階段、下一目標、實際數量與還差多少；展開後顯示簡短故事、最多3筆最近成果及原頁面導覽；資料來源、日期與歷史限制、詳細門檻再獨立收合。最近成果先按日期由新到舊，再放標示「日期未記錄」的既有成果，同課程只出現一次，不加入目前建築階段。領地紀事預設收合，最多保留12筆去重歷史成果。原領主／章節、地圖、編年史、現實活動及首頁讀書入口保留；地圖沒有分階段外觀變化。

測試含門檻前後、實際單元取整、取消、空資料、XP排除、舊打卡／替代／休息、無效／未來／缺日期、重複事件、只讀 getter 與 Mock 重連，以及桌面／手機鍵盤操作。所有自動化隔離正式 Firebase；正式同步與未授權拒絕的人工驗收不由 Mock 代替。

要塞主卡片以「最快達成的建設條件」提示剩餘活動數較少的可用路線（課程單元差距與活動日差距合計；同差距優先學習路線，並不預測完成時間），以該路線中進度最低的必要條件顯示數字與進度條，所有尚缺條件都列在一句話中。學習與跨領域路線另以簡短數量呈現，不顯示百分比。本階段與下一階段的完整路徑條件、差距及達標狀態保留在第三層說明中。跨領域 AND 條件仍取最低完成比例，達標仍以實際單元／日期數判定。第二階段的跨領域路徑只需3個有效活動日，後續階段沿用原課程加活動日門檻。最高階段仍列出兩條路徑的各別狀態；缺課程資料不假設課程條件達標。所有門檻、Firebase Schema、XP、Planner 及原始紀錄保持不變。
